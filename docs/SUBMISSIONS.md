# پیشنهاد تغییر در جدول‌ها با ورود ایمیلی

خواننده‌ها می‌توانند روی هر جدول بنچمارک سه نوع تغییر پیشنهاد بدهند:

- **رتبه‌بندی**: معیار دیگر، ترتیب دیگر، یا کنار گذاشتن ردیف‌ها
- **افزودن نتیجه**: نتیجه‌ی مقاله‌ی خودشان، با لینک مقاله یا آپلود PDF
- **اصلاح عدد**: درست کردن عددی که اشتباه منتشر شده، با ذکر منبع

ورود با ایمیل است: ایمیل را وارد می‌کنند، یک کد شش‌رقمی برایشان فرستاده می‌شود و با آن وارد می‌شوند. رمز عبور ندارد.

## چرا یک سرویس بیرونی لازم است

سایت روی GitHub Pages است و GitHub Pages فقط فایل ثابت نمایش می‌دهد. نمی‌تواند ایمیل بفرستد، کد را نگه دارد یا فایل آپلودشده را ذخیره کند. برای همین سه کار به **Supabase** سپرده می‌شود (نسخه‌ی رایگانش کافی است):

- فرستادن کد به ایمیل و ورود
- نگه‌داشتن پیشنهادها
- نگه‌داشتن PDF مقاله‌ها

بقیه‌ی کار روی GitHub می‌ماند: بررسی، تأیید و به‌روزرسانی جدول.

## مسیر یک پیشنهاد

```
خواننده (سایت روی GitHub Pages)
  │ ۱. ایمیل → کد → ورود                         Supabase Auth
  │ ۲. پیشنهاد + PDF                              Supabase (جدول submissions، پوشه‌ی papers)
  ▼
GitHub Action «Sync reader submissions»  (هر ۱۵ دقیقه)
  │ ۳. بررسی خودکار با scripts/ranking-lib.mjs
  │    معتبر   → یک Issue در GitHub با برچسب ranking (ایمیل در آن نیست)
  │    نامعتبر → رد، با دلیل؛ خواننده دلیل را در سایت می‌بیند
  ▼
شما (مالک مخزن)
  │ ۴. برچسب approved روی Issue  → «Apply approved ranking changes»
  │    → data/rankings.toml به‌روز می‌شود → سایت دوباره ساخته می‌شود
  │    یا بستن Issue بدون تأیید → پیشنهاد «رد شد»
  ▼
۵. همگام‌سازی بعدی وضعیت را برای خواننده «اعمال شد» یا «رد شد» می‌کند
```

فقط برچسبی اثر دارد که **مالک مخزن** بزند.

## راه‌اندازی (یک بار، حدود ۱۵ دقیقه)

### ۱. پروژه‌ی Supabase

1. در [supabase.com](https://supabase.com) حساب و یک پروژه‌ی تازه بسازید.
2. در **SQL Editor** محتوای فایل `supabase/migrations/20261117000000_submissions.sql` را اجرا کنید. این فایل جدول پیشنهادها، قواعد دسترسی (هر کس فقط پیشنهاد خودش را می‌بیند و فقط برای خودش می‌فرستد)، سقف ۲۰ پیشنهاد در روز و پوشه‌ی PDF (حداکثر ۲۰ مگابایت) را می‌سازد.
3. در **Authentication → Providers → Email**، گزینه‌ی Email را روشن کنید.
4. در **Authentication → Email Templates**، در دو قالب **Magic Link** و **Confirm signup** متن را طوری بنویسید که کد را نشان بدهد. مثلاً:
   ```html
   <h2>کد ورود به Pinomics</h2>
   <p>کد شما: <strong>{{ .Token }}</strong></p>
   <p>این کد یک ساعت اعتبار دارد.</p>
   ```
   بدون `{{ .Token }}` به‌جای کد، لینک فرستاده می‌شود.
5. در **Authentication → URL Configuration** آدرس سایت را بگذارید، مثلاً `https://USERNAME.github.io/REPO`.
6. **ارسال ایمیل:** فرستنده‌ی داخلی Supabase فقط برای آزمایش است و در ساعت چند ایمیل بیشتر نمی‌فرستد. برای استفاده‌ی واقعی در **Project Settings → Authentication → SMTP** یک سرویس ایمیل وصل کنید، مثل Resend، Brevo، Postmark یا Amazon SES. بیشترشان نسخه‌ی رایگان دارند.

### ۲. اتصال سایت

در **Project Settings → API** دو مقدار هست: **Project URL** و کلید **anon public**. آن‌ها را در `site/index.html` بگذارید:

```html
<meta name="atlas-supabase-url" content="https://xxxx.supabase.co">
<meta name="atlas-supabase-key" content="eyJhbGciOi...">
```

کلید anon برای انتشار عمومی ساخته شده و گذاشتنش در سایت امن است. آنچه دسترسی را محدود می‌کند قواعد SQL مرحله‌ی ۱ است.

### ۳. اتصال GitHub

در مخزن GitHub، در **Settings → Secrets and variables → Actions** دو secret بسازید:

| نام | مقدار |
|---|---|
| `SUPABASE_URL` | همان Project URL |
| `SUPABASE_SERVICE_ROLE_KEY` | کلید **service_role** از Project Settings → API |

کلید service_role محرمانه است و **هرگز** نباید در سایت یا در کد گذاشته شود. فقط در این secret بماند.

سپس:

- در **Issues → Labels** سه برچسب بسازید: `ranking`، `approved` و `from-site`.
- در **Settings → Pages**، منبع را «GitHub Actions» بگذارید.

### ۴. بررسی

1. سایت را باز کنید، به یک جدول بروید، در «Suggest a change» ایمیل بدهید، کد را وارد کنید و یک پیشنهاد بفرستید.
2. در تب **Actions**، workflow «Sync reader submissions» را دستی اجرا کنید (Run workflow). یک Issue تازه باید ساخته شود.
3. برچسب `approved` را روی آن بزنید. چند دقیقه بعد جدول در سایت عوض می‌شود و وضعیت پیشنهاد برای خواننده «Applied» می‌شود.

## بدون Supabase

اگر دو meta بالا خالی بمانند، دکمه‌ی «Open the suggestion on GitHub» همان پیشنهاد را به‌صورت Issue در GitHub باز می‌کند. این راه حساب GitHub لازم دارد، ولی ورود ایمیلی و آپلود PDF ندارد.

## امنیت

- **محدودیت کاربر:** خواننده فقط می‌تواند پیشنهادِ «در انتظار» برای خودش بفرستد و فقط پیشنهادهای خودش را ببیند. وضعیت را نمی‌تواند عوض کند و در پوشه‌ی دیگران چیزی آپلود نمی‌کند.
- **بررسی متن پیشنهاد:** متن پیشنهاد هرگز اجرا نمی‌شود. فقط به‌صورت TOML یا JSON خوانده می‌شود و هر کلید با جدول مربوط چک می‌شود: معیار و مدل باید وجود داشته باشند، لینک‌ها https باشند و عددها عدد باشند.
- **ایمیل محرمانه می‌ماند:** ایمیل خواننده در GitHub منتشر نمی‌شود. `@` در متن خواننده خنثی می‌شود تا کسی در GitHub صدا زده نشود.
- **سقف:** هر خواننده حداکثر ۲۰ پیشنهاد در روز می‌تواند بفرستد. سقف ارسال ایمیل را هم خود Supabase اعمال می‌کند.

## تست خودکار

```bash
cd tests && npm install && node submissions.test.mjs
```

این تست Supabase و GitHub را با دو سرور محلی جایگزین می‌کند که همان آدرس‌ها و همان قواعد دسترسی را دارند. همه‌ی مسیر را از ورود با کد تا جدول به‌روزشده اجرا می‌کند. workflow «Tests» همین را در هر push روی GitHub اجرا می‌کند.
